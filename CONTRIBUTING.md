# Contributing to Cybercore Tech

Thanks for your interest. These guidelines apply to every Cybercore Tech repository unless a project has its own `CONTRIBUTING.md`.

## Issues

Search existing issues first. When you open one, include:

- **What happened:** a clear description of the bug, feature or bottleneck.
- **How to reproduce it:** exact steps or commands, where they apply.
- **Environment:** OS, versions and any relevant configuration.

Found a security problem? Don't open an issue. See [SECURITY.md](SECURITY.md).

## Pull requests

- **One change per PR.** Don't bundle unrelated fixes.
- **Branch from the default branch** and keep the commit history clean and descriptive.
- **Test before you submit.** It should build without warnings and pass the project's tests (for Rust projects, `cargo test`).
- **Match the surrounding code:** its style, idioms and structure.
- **Say how you tested it** in the PR description.

## Conduct

Keep discussion technical, direct and respectful. The full [Code of Conduct](CODE_OF_CONDUCT.md) applies everywhere.
